# Production setup grounding implementation phases

1. Add a serialized `@tool` SkeletonModifier3D with relative Tree/Player paths, explicit role names, measured skeleton-local up/forward axes and fixed plane/solve limits. Resolve references at runtime; recompute current blend weights/phases/contacts every frame. Preserve original graph clock and root consumer. Reset anchors on inactive binding, configuration changes, timeline jumps/reseek and explicit reset. Expose configuration/order/reach/residual diagnostics.
2. Preflight setup helper ownership and foreign active modifier ordering before any transaction. Create or reuse only the toolkit-owned helper under the resolved Skeleton3D; refuse foreign conflicts and duplicates. Stage helper config, owner, order, instance editability and removal/restoration in the same setup action as clips/Tree. Dry/refusals must remain mutation-free. Return actual helper path/contract metadata.
3. Change saved setup qualification to require the actual saved owned helper and exact bindings/config. Capture final bone snapshots inside its `modification_processed`; never install a prototype. Wrong/missing/disabled bindings and later writers fail ownership/witness even when raw clip endpoints happen to be valid.
4. Add source-prepared tests for creation/reuse/serialization/Undo/Redo/dry/refusal and runtime dynamic quarter/half/three-quarter/ramp/reseek scenarios, plus disabled/wrong-order corruption. Preserve exact standalone clips/accepted fixtures; collect source-only diff and protected blob evidence. Native/editor execution waits for root's FX queue to finish. No numerical or candidate pass is inferred from prepared tests.

Production is limited to the existing level ankle-plane setup contract, not arbitrary terrain, controller yaw or physics collision. Existing standalone authoring recipes and graph clock remain unchanged. The controlled prototype evidence is in `setup-grounding-prototype.md`; production wiring requires fresh saved public scenes and independent assessment.
