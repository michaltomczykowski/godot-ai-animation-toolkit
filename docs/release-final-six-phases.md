## Execution limits

- One active workstream, at most one focused worker. Root owns the engine queue.
- No new tool families, demo rebuild or general audit framework.
- Reuse exact relevant passing evidence. Preserve goldens, original failed
  receipts and author state. Never loosen physical or parity thresholds.
- Keep implemented, verified and release-ready separate. No aggregate percent.
- After each phase update FIX_ROADMAP and AGENTS with changes, actual results,
  pushed source, remaining failures and the exact next command.
- A blocked Linux phase does not prevent completing independent phases3–5;
  publication remains blocked. Engine/platform requirements cannot change
  silently. No startup sleeps, save retries or lucky-green crash approval.

## Later phase implementation

queue-synchronization experiment must cover all queue writers and completion
handoff without holding a lock across loading or thread joins. It cannot
qualify an unmodified official engine. No supported toolkit barrier has been
established; do not invent one. Preserve original crash evidence.

jump height/timing and strafe travel to explicit requests or measured-rig
defaults. Start/stop require accepted idle/walk endpoint references and an
independent travel expectation; setup requires actual request/graph/scene joins.
Scope only the cases actually verified, not all parameter combinations.

Phase4 runs native admission,framing probe,continuous capture,full decode and
independent assessment in that order. Reuse existing saved outputs and eligible
sequence footage. Static evidence is allowed only for static effects. Private
XBot media stays local and is not copied to public release evidence.
